Handling OTU tables

Before any statistical analysis, the raw OTU tables must be cleaned so that the downstream results reflect the true biological signal rather than technical noise. The steps below should be applied in the order presented, since each script loads the phyloseq object saved by the previous one (e.g., otu_ctrl_clean → otu_rare_clean → otu_BLAST_clean).

TipStart from the data preparation step

All scripts in this section assume that your raw data has already been converted to a phyloseq object and saved as .RData. If this is not the case, go through Data preparation first, and make sure that the required packages are installed and loaded.

Dealing with controls

Negative controls, blanks and positive controls are used to verify that the full workflow (from DNA extraction to bioinformatics) behaved as expected. Inspect them, remove contaminants, and then remove the controls themselves from the data set.

  • Dealing with positive controls: identify the synthetic community and confirm that taxonomic profiles match expectations
  • Dealing with negative controls (and blanks): inspect library sizes, find contaminants with the R package decontam, and remove low-quality samples

Filtering OTU tables

Remove OTUs that are artefacts or that cannot be reliably identified, and clean the taxonomic assignations.

  • Global filtering
    • Taxonomy filtering: keep only the organisms targeted by the primers
    • Singletons and rare OTUs: remove OTUs based on absolute or relative abundance thresholds
  • BLAST quality check
    • BLAST filtering: remove short or poorly aligned sequences
    • BLAST cleaning: remove unknown organisms and replace low-confidence taxonomic assignations with NA

Rarefaction and normalization

Account for differing sequencing depths across samples before comparing communities.

  • Rarefaction: draw rarefaction curves, choose a sufficient depth, and check whether library sizes are balanced between groups
  • Transformations: alternatives that preserve all reads, such as relative abundance, Hellinger, CLR and robust CLR
